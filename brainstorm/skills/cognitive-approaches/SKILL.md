# Cognitive Approaches

Choose a change in representation or operation that makes the difficult part inspectable. Do not recite a roster of famous thinkers or perform all four approaches regardless of the task.

## Match the operation to the obstruction

| Obstruction | Approach | Concrete move | What would show it helped |
|---|---|---|---|
| The explanation is abstract, static, or difficult to check | **Feynman-style visualization** | Walk one real example; draw a state transition, timeline, spatial relation, or input/output trace | The disputed behavior becomes explicit enough to test or falsify |
| Effort is spread across many apparent problems | **Hamming-style constraint focus** | Identify the specific dependency limiting the desired outcome; compare the effect of changing it with changing a non-binding part | The proposed intervention changes the outcome rather than just a local metric |
| Repeated intervention creates resistance or more work | **Taoist-inspired flow** | Examine the actual incentives, capacities, defaults, and feedback; consider shaping an existing tendency instead of adding force | A lower-burden action achieves the same goal without transferring costs or losing control |
| Working memory or verbal reasoning hides a relation | **External cognitive faculties** | Make a small table, sketch, executable example, or intermediate artifact using available tools | A contradiction, missing state, or decision becomes visible that prose obscured |

The names are reminders, not historical quotations. If a quotation's source cannot be verified, say that you cannot establish it—not that no such source exists. Do not invent citations, ascribe intentions to the universe, or claim access to hidden model activations. "The system wants" must cash out as an observed mechanism, not mysticism presented as fact.

## Keep the representation honest

Preserve the units, ordering, ownership, and constraints relevant to the decision. A clean drawing can still omit the event that matters. For stateful workflows, show what can happen between an external action and its acknowledgment or record; test interruptions rather than assuming a tidy happy path proves recovery.

Use the smallest representation that exposes the live uncertainty. Do not build a diagramming system, a new tracking file, or an elaborate model to answer a small question. Reuse the actual artifact where possible.

## Test the change in thinking

Identify what was unclear, apply one promising operation, and check whether it changes the next justified action. If it only produces nicer language, switch operations or obtain missing evidence. If the answer is already clear, act within the task's authorization rather than adding a mental-model ceremony.

A representation can generate an explanation; observations or tests must still establish its truth. Label assumptions and test a boundary case that could break the model. Stop once the task has a supported next step or the particular missing fact is named.

Deliver the useful representation, the constraint or insight it exposes, and the resulting action or check. Explain the mental model only when the user is learning the method.

**Change how the problem can be inspected, not just how intelligently it is described.**
