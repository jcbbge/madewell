skills: designing-apis, repo-deep-dive-analysis

Here the thing being made is code, and the check is its tests.

- Ground in the code base: the stack actually in use (framework, database, libraries), the
  schema, the API, and the existing utilities to reuse. Search the repo and cite `path:line`
  for each. A plan for React in a Solid app, or MySQL in a Postgres app, is the failure this
  act prevents.
- Sirius's track names the files to change. Orion's track names the tests and where they go:
  the test paths are `tests/`, `test/`, `__tests__/`, `spec/`, `specs/`, or a file named
  `*.test.*`, `*.spec.*`, `*_test.*`. Never assign a test to Sirius.
