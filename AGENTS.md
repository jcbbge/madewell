# Made Well

Read FOUNDATION.md before changing this application. OPERATIONS.md is the practical entrypoint; README.md defines CLI/API and cartridge contracts; DESIGN.md governs views.

Capture input → generate tasks → complete tasks. The work item is durable; agents and scratch directories are disposable. Every selected task owes ideation, planning, implementation and independent verification, with depth proportional to the task. Stage names grant no execution authority.

Before acting identify revision, target worktree, selected MW_HOME/MW_STORE, prescriptions and runner owner from actual supplied context/read surfaces. Work only in the assigned disposable worktree. Never commit, branch or push without explicit authority; Made Well delivers maker changes. Never edit a live database to manufacture progress. Observers remain read-only and never move work.

Apply context → repository purpose → DX/UX/AX matrices before choices. Record pass, cell, gains, costs and why. Three hits: all-three; two: at-least-two; fewer: reshape or stop. Optional decision cartridges advise only. No inference provider or automatic signal-driven steering exists.

Every handoff uses NQ. Profiles only. Answer once, retain aliases and reuse references, including explicit ancestry. Three answered turns with open questions hold for a specification defect. Makers stay private. Implementation follows its accepted fixed brief. Independent acceptance is owned by the test architect, outside the plan's scope. The implementer may maintain existing, explicitly scoped regressions only as required by the plan. The implementer may run `npm run bundle` solely when the fixed brief requires generated product artifacts, and includes the generated tracked files in its change. Neither maker runs tests, typechecks, acceptance or verification commands, nor commits, branches or pushes; Made Well owns candidate build/check acceptance and delivery. Made Well builds `npm run bundle`, runs affected tests and relevant `npm run typecheck`; no mandatory whole-suite run per change.

Use TypeScript with erasable syntax and Effect. Store/Worker are Context.Service layers; engine functions use Effect.fn and Clock. SQLite Store owns atomic revision transitions, events and retry receipts. Save every boundary before another call; recovery redrives saved state. Returns received during blockers remain pending. Request IDs bind recursively sorted validated input and survive pruning. Stale revisions never overwrite concurrent changes.

New work has schemaVersion 2 and no registration or location requirement. Installation defaults live in the singleton settings row and are snapshotted on creation. Default delivery is external work with an owner. Open external work never enters the runner. Prerequisites release only on completed, never dropped. Progress, blockers and completion use supported commands/API and load no worker or prescriptions.

Runnable cartridges require runtime functions and execution contract 2. Leaves declare agent or command, object output, replay, writes and onFailure; groups sequence or privately parallelize. Job names carry no behavior. Explicit replay and destination writes never rewind automatically. Independent acceptance must bind current conditions and producer output. Saved assertions, historical success and automated acceptance remain visibly distinct.

Ground, Rumen and preparation are mandatory on every configured consumer. Ground actual source, permitted outputs and declared bindings. Rule accounting is not proof of executed checks. Superseded source hashes invalidate preparation. Keep blocked partials and all prior evidence. Never expose private sibling outputs, facts, NQ or maker history.

Node cwd is scratch. Persist results and file observations before cleanup. Only settings grant absolute destinations; file results declare destination/path/hash/bytes and are checked without following symlinks. Readers show saved observations, never fetch files. Keep process-group cleanup and teardown cwd. Legacy obligations are inert until explicitly configured. Alerts use pinned run/cwd and record attempts; never resend an uncertain attempt automatically.

Resource-governed admission remains the default: sample memory, CPU and disk before launches, preserve resource-wait/resource-admitted evidence, and retain explicitly configured positive concurrency limits. No always-on service is installed by this wiring. Browser foreground driving follows only explicitly selected roots and their links.

All CLI output is JSON. Errors are MadeWellError(code,message,context,cause?,next). Reads use the read-only Store open: no mkdir, DDL or journal changes. Keep Host/Origin/CSRF/body protections, exact source and durable browser drafts. UX/DX/AX are read-only lenses on one trace; unknown metrics stay unknown. Use local Plex Sans prose/Plex Mono system messages and native keyboard controls.

Historical pins and artifact exports stay readable through legacy decoders. Migration alone retires the historical registry through preview/token/attestation/journal and exact-file removal. Never execute legacy commands or delete registered directories. Installed cutover needs its own rollout receipt; isolated verification is not that receipt.
