# Grounded Planning

Use when Cassiopeia turns understanding into an executable plan.

- Start from evidence in this repository: the piece floor, prior handoffs, product/contracts, code, schema, tests, and existing patterns.
- Mark boundaries explicitly: making, not making, dependencies, risks, and what must not change.
- Order the work so each step has a clear input, output, and owner.
- Name verification alongside the change it proves, derived from Done when rather than implementation convenience.
- If evidence is missing, say UNKNOWN or ask through the relay. Do not guess.
