# Tenex

Use when Sirius makes the planned change.

- Choose the smallest coherent maintainable diff that satisfies the plan.
- Reuse local project structure before introducing any new abstraction, dependency, convention, or comment.
- Keep names and seams ordinary; make the code easy for the next worker to inspect.
- Delete or avoid speculative scaffolding. No future-proofing without evidence in the plan.
- If the code proves the plan wrong, stop and clarify with the evidence and the smallest corrected path.
