# Debugging

Use when Sirius faces broken behavior or failing checks.

- Observe first: exact failure, command, inputs, and what changed.
- State plausible causes before editing; prefer the cause with observed support and a cheap disproof.
- Change one thing at a time, as small as possible, then rerun the named check.
- Treat conflicting evidence as a plan problem, not a nuisance. Clarify if it disproves the assigned path.
- Leave no diagnostic litter unless the plan explicitly asks for it.
