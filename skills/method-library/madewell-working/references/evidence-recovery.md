# Evidence, recovery, and reorientation

## Design evidence before making

Each acceptance condition needs a stable identity, observable claim, actual artifact/result version, authorized evidence producer, accessible inputs, and the boundary at which those inputs exist. A planned artifact is not an existing result. Keep source identity, result identity, mechanical execution, independent judgment, manual verdict and live observation distinct.

A candidate checker can inspect the candidate, fixed plan and explicitly provisioned environment after implementation and before verification. It cannot use its own future finished report as a precondition, the maker's inaccessible private history, future shipment, a manual verdict not yet made, or unavailable production access. Give live checks, engine provenance and operator judgment their own owners and timing. If an owner lacks inputs or permission, repair provisioning or retain the condition as unknown; do not weaken it.

For software's independent acceptance split, check design and implementation receive the same fixed plan without seeing each other's private making. Only the authorized executor combines actual candidate and checks. A new profile label does not establish independence. Maintenance of existing regression tests, if required by a fixed brief, remains distinct from authorship/execution of independent acceptance checks.

Retain condition → evidence links with producer, operation/observation, actual outcome, source/result version and limits. Record not-run and unavailable as such. A valid shape, matching digest, successful transport, process exit, declaration of completion or publication cannot by itself establish the required outcome. An attributed external completion assertion is not independent verification. Source acceptance, packed portability, native loading, actual instruction application and live usability each need their own evidence when claimed.

## Recover from the saved boundary

Keep exact inputs, selected method bytes/identity and effort, occurrence/attempt identity, accepted versus attempted contributions, partial/refused results, questions/answers, effect receipts and pending drafts. Use existing persistence, retaining the transition before a successor proceeds; do not invent a second ledger. Record the lack of durable storage when using only a conversation.

On interruption, inspect saved state and actual authorized effect evidence. Resume from the established boundary; do not rerun accepted work or reinterpret an old attempt using new defaults. Reuse the same logical operation identity and exact input to recover an uncertain receipt. A timeout is not proof of failure. Changed inputs require a deliberate new operation after reviewing the conflict; do not choose a fresh ID to evade an uncertain prior effect.

An explicit plan/source/method change preserves historical evidence and marks stale preparations/evidence stale. Reprepare only affected successors. Releasing a dependency does not release an NQ hold, checkpoint or uncertain-effect stop, and prerequisite success does not prove the consumer now passes. Retain the consumer's exact resumption action and required evidence.

Clean up only owned disposable resources after retaining required evidence. Do not delete referenced results, another owner's work or private recovery material. A skill cannot grant persistence, authentication, filesystem access or exactly-once effects; report actual host limitations.

## Reorient from zero remembered context

Return the smallest self-contained account of intended outcome, actual acceptance conditions, evidenced result, missing completion-critical work, actual activity, next owner/action and whether a human decision is needed. Done and needs-human are independent questions. Unfinished work can stay with its owner; no question for the human does not mean anyone is working.

Use current evidence for “in flight.” If stopped, stale or unknown, say so. A summary is a view of the existing record, not a scheduler, retry or approval. Link authorized exact evidence behind abbreviated views. Avoid fictional percentages, inaccessible model internals or repeated completion claims treated as independent proof.

**Example:** “Source draft exists; independent review has not run. Owner: verification. Next: compare version A-4 to conditions C-1/C-2 using the provisioned source. No human decision needed; execution is currently stopped.” This restores control without inventing activity or acceptance.
