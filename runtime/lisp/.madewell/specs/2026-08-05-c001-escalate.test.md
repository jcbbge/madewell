## 4. The resume-in-place proof (the finding this package exists to deliver)

`answer-resumes-in-place` arranges a worker with observable side effects before and
after the stop:

```
(push :before-1 log) (push :before-2 log)
artifact ← (list :allocated-before-the-stop)   ; fresh heap object, stashed outside
ruling   ← (escalate "c001-t2: continue?" :default :no-ruling)
(push (list :after ruling (eq artifact stash)) log) (push :after-2 log)
:worker-ran-to-completion
```

The handler invokes `answer` with `:ruled-go`. The suite then asserts, together:

1. the worker returned `:worker-ran-to-completion` (control flowed out the tail);
2. the condition fired **exactly once** (no double-signal);
3. the log is *exactly* `(:before-1 :before-2 (:after :ruled-go t) :after-2)` —
   before-parts ran **once** and in position, after-parts ran **after**, carrying the
   supplied value;
4. the artifact allocated before the stop is `eq` to itself after resumption —
   lexical state was not rebuilt or copied.

Exact-trace equality is structural, not counter-based: a re-run implementation
duplicates `:before-*`; an unwind loses `:after-*`; a substituted ruling fails (3);
a reconstructed frame fails (4); a double signal fails (2). The same trace shape is
reused for `use-default` and for the indistinguishability test (intent 3).

**Result: resume-in-place is genuine.** The worker continues from the exact point it
stopped; nothing is re-run.
