## Spec Under Test (restated from the package brief — the only authority)

`bin/claim-gate.sh`:

1. **S1 Usage:** `claim-gate.sh <worker-name> <topic> [timeout-seconds]`, default timeout 120.
2. **S2 Match:** polls `~/.tower/board.jsonl` for a `type:"claim"` line whose `from` equals the
   worker name AND `topic` equals the topic AND `cwd` equals the current directory (`$PWD`).
3. **S3 Hit:** exit 0 and print the matching claim line the moment it appears.
4. **S4 Timeout:** exit 1, printing to **stderr**: the wait duration, the exact match criteria
   used, and the last claim lines seen for that topic (any cwd) as diagnostic.
5. **S5 Arg/board errors:** exit 2 with usage on wrong arguments; exit 3 if the board file
   does not exist.
6. **S6 Read-only:** never writes to the board, never truncates anything; read-only on the
   filesystem.

Risk-derived requirements (package brief, *What Could Go Wrong*):

- **R1 Over-matching:** a claim with the right topic but wrong cwd, or wrong worker, must NOT
  open the gate.
- **R2 Fail-closed on format drift:** wrong assumptions about the JSONL shape → timeout
  (acceptable), and the diagnostics must make the cause obvious.
- **R3 Never fail open:** every non-match path (no match, empty file, garbage lines) exits
  non-zero.

## Safety Rules (board discipline — binding on the Runner)

- Synthetic claims are appended to the real board by the suite. This is sanctioned by the
  package brief: append is the board's write path, and a test claim with a unique topic is
  honest use, not pollution.
- All synthetic topics match `claim-gate-test-<pid>[-tNN]`; all synthetic `from` fields match
  `cg-(test|other)-worker-<pid>`; every synthetic body says it is a synthetic test claim.
- **The suite never deletes, edits, or truncates board lines. No cleanup — the synthetic
  claims stay (append-only).** Do not "tidy" the board afterwards.
- Missing-board, empty-board, malformed-board, default-timeout, and read-only cases run with
  `HOME` pointed at a `mktemp -d` directory. **The real board path is never referenced by
  those cases.** (T05 additionally checksums the real board before/after to prove it.)
- The suite makes no commits and changes no repo files. Its only writes: board appends
  (sanctioned) and its own `mktemp` scratch dir (removed on exit).
- Every gate invocation is bounded by a watchdog; the suite leaves no orphan processes.

## What Could Go Wrong (in the tests themselves)

1. **Board growth:** each full run appends 4 synthetic claims to the real board (T01, T02,
   T03, T06). Sanctioned, clearly synthetic, no cleanup — but repeated runs accumulate; that
   is expected, not a defect.
2. **T08 cwd-listing race:** the `ls -A` assertion assumes no top-level file creation in the
   repo root during its ~2 s window. Run only after the Implementer's DONE; if T08 fails with
   unchanged board checksums, re-run once before sending to triage.
3. **Timing sensitivity:** T02's elapsed ≥ 2 s is deterministic by construction (the claim
   cannot exist before the append). T11's 100–180 s window tolerates poll-interval and load
   jitter; a borderline T11 failure should be re-run once before triage.
