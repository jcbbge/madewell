Lisp, from a
standing start

The second-oldest major language family still alive, invented for AI research in 1958, and the only one where your program's syntax and your program's data structure are the same thing. Everything below is the high-level map: what it is, why it exists, and how you actually write it.

Origins

Built for AI, twenty-five years early

John McCarthy created Lisp at MIT in 1958, publishing the design in "Recursive Functions of Symbolic Expressions and Their Computation by Machine, Part I" (CACM, 1960). The name means LISt Processor. The motivation was explicit: an AI programming language for the IBM 704 — symbolic computation, not number crunching, at a time when Fortran was the only alternative that mattered.

Two accidents shaped everything. First: McCarthy designed a human-friendly surface syntax ("M-expressions") that would compile down to the parenthesized internal form ("S-expressions"). Programmers tried both and chose the internal form — M-expressions were abandoned, and Lisp's famous parentheses are the result of users voting for the AST. Second: McCarthy's paper defined eval as a theoretical construct, and his student Steve Russell hand-compiled it into 704 machine code — over McCarthy's objection that he was "confusing theory with practice." The result was the first Lisp interpreter, and with it the REPL: the read-eval-print loop that every interactive language since has been imitating.

The pedigree is absurd. Lisp is credited with first-class functions, automatic garbage collection (Daniel Edwards, pre-1962), conditionals beyond goto (McCarthy invented if-then-else), the symbol type, programs made entirely of expressions, and the first self-hosting compiler (1962, written in Lisp itself). Half of modern language design is Lisp features arriving on a forty-year delay.
The Kernel

Code is data

This is the one idea everything else hangs off. A Lisp program is not text that a parser turns into a hidden tree — a Lisp program is written directly as the tree, in lists. The same lists the language manipulates as data.

;; this is a list of three things: a symbol and two numbers '(+ 1 2) → (+ 1 2) — quoted: it's data ;; the same list, unquoted, is a program (+ 1 2) → 3 — evaluated: it's code

the quote mark is the entire boundary between program and data

In TypeScript terms: imagine writing your source directly as the Babel AST, where escodegen and JSON.parse are the same function. The property is called homoiconicity, and Lisp was the first language to have it. Its practical payoff is macros — functions that run at compile time, take your code as a list, and return new code — which is how Lisp grows domain-specific languages from inside itself.

The Family

One family, many dialects

LISP 1.5
The first widely distributed version, MIT. The trunk of the tree.
MacLisp / Interlisp
The 1970s power dialects — MIT's Project MAC and BBN respectively. Both fed into what came next.
Scheme · 1975
Steele & Sussman's minimalist redesign. Small, elegant, academic. Racket is its modern descendant.
Common Lisp · 1984
The industrial consolidation — described in Common Lisp the Language (1984), standardized as ANSI X3.226-1994. Big, pragmatic, multi-paradigm. The standard has not needed changing in thirty years.
Emacs Lisp
The scripting language of Emacs; the most-run Lisp on Earth by accident.
Clojure · 2007
The modern hit — a Lisp compiled to the JVM, immutable-first, functional. Not Common Lisp; different semantics.
This primer is about Common Lisp, specifically as implemented by SBCL (Steel Bank Common Lisp) — the fast, actively maintained, native-compiling implementation that ships monthly releases. When people say "Lisp" in a systems context in 2026, this is usually what they mean.
Syntax · All of It

You already know the whole grammar

Lisp syntax has two categories. Atoms: numbers (123, 3/7 — yes, real rationals — 1.0), strings ("foo"), and symbols (names like hello-world). Lists: anything in parentheses, nesting arbitrarily. That is the entire grammar. There are no statements, no operators, no precedence table — everything is an expression and everything returns a value.

;; every call is (verb argument argument ...) — prefix, always (+ 1 2) → 3 (* (+ 1 2) (- 3 4)) → -3 — nesting is precedence (string-upcase "hej") → "HEJ" ;; comments are semicolons

Three rules of the road, and the rest is vocabulary:

evaluation
A form (f a b) evaluates a and b, then calls f. A handful of special operators (if, quote, let…) bend that rule. Macros are the third kind of form — they rewrite code before it runs.
truth
nil is the only false value; everything else is true. t is the canonical true. nil and the empty list () are the same object — a famous, load-bearing pun.
case
The reader upcases unescaped names: foo, Foo, FOO are the same symbol. In practice you write everything lowercase and never think about it.
Vocabulary · Variables

Bindings, not declarations

;; globals — the *earmuffs* are a naming convention for special vars (defparameter *model* "claude-sonnet-4.5") ; always re-sets on reload (defvar *cache* nil) ; sets only if unbound ;; locals — let opens a scope, like a block-scoped const (let ((x 10) (y 20)) (+ x y)) → 30 ; bindings end with the closing paren ;; let* lets later bindings see earlier ones (let* ((x 10) (y (* x 2))) y) → 20 ;; setf is THE assignment operator — works on any "place" (setf x 42) (setf (gethash "k" table) "v") ; like table["k"] = "v"

defparameter ≈ let-at-module-scope · let ≈ { const } block · setf ≈ = for anything

The convention system does real work here: *earmuffs* mark global/special variables, +plus-signs+ mark constants, and hyphenated kebab-case is universal — hello-world, never helloWorld.

Vocabulary · Functions

defun, lambda, and the two namespaces

;; the workhorse — docstring is part of the language (defun hello (name) "Say hello to `name'." (format t "hello ~a !~&" name)) (hello "jrg") ; last expression is the return value — no return keyword ;; optional and keyword parameters (defun hello (name &optional age) ...) (defun hello (name &key (happy t) lisper) ...) (hello "me" :lisper t :happy nil) ; named args, any order ;; rest args (defun mean (x &rest numbers) (/ (apply #'+ x numbers) (1+ (length numbers)))) ;; anonymous functions (lambda (x) (* x 2)) (funcall (lambda (x) (+ x 1)) 5) → 6

One genuine oddity to internalize early: Common Lisp is a Lisp-2 — functions and variables live in separate namespaces. A symbol can name both at once. So when you pass a function as a value, you reach into the function namespace with #' (sharp-quote), and you call a function held in a variable with funcall:

(mapcar #'1+ '(1 2 3)) → (2 3 4) ; #' = "the function named…" (funcall #'+ 1 2) → 3 (apply #'+ '(1 2)) → 3 ; apply spreads a list

TS: passing `fn` vs calling `fn()` — CL makes the distinction explicit with #' and funcall

Functions can also return multiple values natively — (values 1 2), captured with multiple-value-bind — without allocating a tuple. The second value simply vanishes unless you ask for it.

Vocabulary · Control Flow

Everything returns a value

;; if is an expression — like a ternary, always (if (> x 3) "big" "small") (when ready (launch)) ; if with only a then-branch, many forms (unless ready (wait)) ; inverted when ;; cond is the if/else-if chain — first true clause wins (cond ((< n 0) :negative) ((zerop n) :zero) (t :positive)) ; t = the else clause ;; case is switch (case phase (:imagine (dream)) (:plan (draft)) ((:make :verify) (build)) (otherwise (rest)))
Vocabulary · Iteration

Three tiers of looping

Simple counting and list-walking have dedicated forms; loop is the kitchen-sink macro (a small DSL — this is macros earning their keep); and the functional tier maps and reduces like you're used to.

;; tier 1 — the simple forms (dotimes (n 3) (print n)) ; 0 1 2 (dolist (item '(1 2 3)) (print item)) ;; tier 2 — the loop macro, an embedded iteration language (loop for x in '(1 2 3) collect (* x 10)) → (10 20 30) (loop for i from 0 below 3 collect i) → (0 1 2) (loop for x in '(1 2 3 4 5) when (evenp x) collect x) → (2 4) (loop for x in '(1 2 3 4 5) while (< x 4) collect x) → (1 2 3) (loop for k being the hash-key of *table* collect k) ;; tier 3 — functional, closest to TS .map/.reduce/.filter (mapcar (lambda (x) (* x 10)) '(1 2 3)) → (10 20 30) (reduce #'+ '(1 2 3 4)) → 10 (remove-if-not #'evenp '(1 2 3 4)) → (2 4)
Vocabulary · Data

Cons cells all the way down — plus real structures

The primordial structure is the cons cell: a pair of pointers. Lists are chains of them. The accessors car (first) and cdr (rest) are 1958 IBM 704 register names — Contents of the Address/Decrement part of Register — fossilized into every Lisp since.

(cons 1 2) → (1 . 2) ; a pair (list 1 2 3) → (1 2 3) ; chained conses (car '(1 2 3)) → 1 ; head — also: (first ...) (cdr '(1 2 3)) → (2 3) ; tail — also: (rest ...) ;; and the modern structures TS would expect #(1 2 3) ; vector — real O(1) arrays (make-hash-table :test #'equal) ; hash map (gethash "key" table) ; read — setf-able to write "strings", :keywords, 'symbols ; keywords are self-evaluating atoms

One honest wart, named now so it never bites: equality is a zoo. eq (identity), eql (identity + same number/char — the default), equal (structural for lists/strings), equalp (looser still). The TS analogue is === vs deep-equal, except there are four of them. Rule of thumb: eql for atoms, equal for lists and strings.

The Power Tools · Macros

Functions that run on your code

A macro receives its arguments unevaluated, as lists, and returns a new list that becomes the code. The backquote ` is a template; comma , splices values in. This is how loop, defun, and half the "language" are implemented — in the language.

;; a control-flow construct TS would need a TC39 proposal for (defmacro with-timing ((label) &body body) `(let ((start (get-internal-real-time))) (prog1 (progn ,@body) (format t "~a took ~ams~&" ,label (- (get-internal-real-time) start))))) ;; and now it's just… syntax (with-timing ("pantry-search") (search-pantry query))

every (with-…) idiom in CL is this move: acquire, run body, release — impossible to forget the cleanup

Discipline note: the community rule is "macros last." If a function can do it, use a function. Macros are for when the shape of the code itself must change — new binding forms, new control flow, embedded DSLs.
The Power Tools · CLOS

Objects, inverted

The Common Lisp Object System will feel upside-down for about a day, then permanently better. Classes hold data. Methods do not live inside classes — they live on generic functions, and they dispatch on the types of all their arguments, not just the first.

(defclass worker () ((name :initarg :name :accessor worker-name) (state :initform :idle :accessor worker-state))) (defgeneric handle (agent message)) ;; dispatch on BOTH argument types — multiple dispatch (defmethod handle ((w worker) (m task-message)) ...) (defmethod handle ((w worker) (m kill-message)) ...) (defmethod handle ((c coordinator) (m escalation)) ...)

In TS you'd simulate the third case with a visitor pattern or a tag-switch. Here the dispatch table is the language. There are also :before, :after, and :around methods — middleware as a built-in — and classes can be redefined while instances are live, which matters for a runtime that never restarts.

The Power Tools · Conditions

Not exceptions. Something better.

The headline feature for runtime work. handler-case looks like try/catch and unwinds like it. But handler-bind runs your handler before the stack unwinds — the computation is still alive, paused at the signal point — and the handler can invoke a restart to resume it in place.

;; try/catch equivalent — unwinds, familiar (handler-case (risky-thing) (network-error (e) (log-and-fallback e))) ;; the real mechanism — low level offers recoveries, high level picks one (restart-case (parse-entry line) (skip-entry () nil) (use-value (v) v)) (handler-bind ((parse-error (lambda (c) (invoke-restart 'skip-entry)))) (parse-all-entries file)) ; bad lines skipped IN PLACE — the loop never dies

Three parties, decoupled: the signaler (detects the problem), the restarts (know the local recoveries), the handler (owns the policy, possibly far up the stack). TypeScript collapses all three into throw/catch and loses the stack in between. This is the primitive the runtime-convergence verdict is built on.

The Workflow

You develop inside the running program

The deepest workflow difference, and the one nobody warns you about. There is no edit → save → restart cycle. You start SBCL once — the image — and then compile individual functions into it while it runs, with a keystroke from your editor. State survives. The program never stops.

the REPL
Not a scratchpad bolted on — the primary interface. You build the system by talking to it.
redefinition
Redefine a function, a method, even a class, in a live image. Instances update. The 3am debugging move: fix the bug inside the failing run, then resume it with a restart.
the debugger
An unhandled condition drops you into an interactive debugger at the point of failure, stack intact, restarts listed. Nothing has unwound. You can inspect, fix, and continue.
save-lisp-and-die
Snapshot the entire living image to a single executable. Your built-up state ships as the binary — ~12 MB compressed, <50 ms startup.
Tooling honesty: this workflow is first-class in Emacs (SLIME/Sly) and nowhere else yet — the VS Code extension (Alive) is pre-MVP. Budget for that, or wire the REPL into your AI harness via MCP and let the agent be the editor integration.

The language was built in 1958 to do symbolic computation for AI. The models do the reasoning now — and the thing Lisp was always best at, programs as data, computation that inspects and transforms itself, turns out to be a fair description of an agent runtime.
